**All three are different.** The CI commands execute without error (bash -e), but Gradle never uses the keystore we provide.

### Root Cause

Capacitor's `npx cap add android` generates `android/app/build.gradle` **without any `signingConfigs` block**. Gradle falls back to its default behavior: auto-generate a random debug keystore on every build. Copying a keystore to `android/app/debug.keystore` has no effect because Gradle never reads it — it creates its own.

### Why Previous Agents Missed This

The initial diagnosis focused on **file placement** (where is the keystore? is it in the right directory?) rather than **Gradle configuration** (does Gradle know to use it?). This is the classic "the file is there but nobody's looking at it" problem.

### Also Pending: About Modal Version Sync

The About modal in `templates/index.html` hardcodes its version number. `showAbout()` never dynamically updates it from `CLIENT_VERSION`. A fix was proposed (`document.getElementById('aboutAppVersion').textContent = CLIENT_VERSION`) but not implemented.

## Immediate Next Steps

### Step 1: Fix the real problem — inject signingConfigs into Gradle

The `android/app/build.gradle` generated by Capacitor needs a `signingConfigs` block. Two approaches:

**Approach A: sed injection in CI (recommended — simple)**

In `deploy.yml`, after `npx cap add android` and after copying the keystore, inject signing configs:

```yaml
- name: Inject signing config into build.gradle
  run: |
    cat >> android/app/build.gradle << 'GRADLE_EOF'

    android {
        signingConfigs {
            debug {
                storeFile rootProject.file('debug.keystore')
                storePassword 'android'
                keyAlias 'androiddebugkey'
                keyPassword 'android'
            }
        }
        buildTypes {
            debug {
                signingConfig signingConfigs.debug
            }
        }
    }
    GRADLE_EOF
```

**Approach B: Capacitor variable injection**

Add to `android/variables.gradle` (if it exists) or create a Capacitor hook.

## Potential Gotchas
- When injecting with `cat >>`, ensure the appended block doesn't conflict with existing `android {}` blocks (nested `android {}` inside `android {}` may cause Gradle error). Check the generated `build.gradle` structure first.
- Always verify signature consistency by downloading 2 consecutive CI builds and comparing CERT.RSA fingerprints.
- Don't confuse `android/` being gitignored — you must inject signing configs in CI, not commit modified build.gradle.

## Do Not Repeat
- Do NOT attempt to fix signature conflict by only placing/copying a keystore file without modifying Gradle config.
- Do NOT assume `base64 -d` in CI produces a usable keystore — even when it runs without error, Gradle may ignore it.
- Do NOT evaluate checkAppUpdate without exposing it to `window`.
